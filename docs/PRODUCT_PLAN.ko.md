# OhMyContext 제품 기획안

최종 수정: 2026-08-24
상태: 개발 기준선

## 1. 제품 한 문장

OhMyContext는 개인이 합법적으로 확보한 블로그, 노트, 일기, 커뮤니티 글, 문서 내보내기를 자신의 PC에 모아 출처가 보존된 개인 지식 자산으로 만들고, Claude·Codex 등 MCP 호환 AI가 사용자의 허용 범위 안에서 검색하도록 돕는 데스크톱 앱이다. 프로젝트 라이선스를 선택한 뒤 오픈소스로 공개할 예정이다.

이 제품은 새로운 채팅 앱이 아니다. 장기적으로 수집, 정규화, 출처, 검색, 권한, 삭제, 이식 가능한 내보내기를 담당할 **개인 컨텍스트 계층**이다. 현재 개발자 알파에는 폴더 가져오기, 로컬 검색·조회, 출처 제거, 내장 샘플, 내용 비공개 접근 이력, Codex·Claude Code 연결/해제가 구현되어 있다. 이식 가능한 내보내기와 일반 커넥터, Claude Desktop Extension은 후속 범위다. 답변 생성과 모델 선택은 사용자가 이미 쓰는 AI 앱에 맡긴다.

## 2. 해결할 문제

개인의 디지털 기록은 서비스별로 흩어져 있고, 검색 방식과 내보내기 형식이 서로 다르다. 일반 사용자가 이를 AI에 활용하려면 다음 중 하나를 감수해야 한다.

- 매번 필요한 글을 찾아 복사해 붙여 넣는다.
- 전체 자료를 특정 클라우드 서비스에 다시 업로드한다.
- 임베딩, 벡터 DB, API 키, Docker, MCP 설정을 직접 다룬다.
- 출처와 삭제 관계가 사라진 데이터 묶음을 만든다.

OhMyContext의 목표는 이 과정을 “연결 또는 가져오기 → 확인 → 검색 → AI 연결”의 데스크톱 경험으로 줄이면서도, 어떤 원문에서 나온 정보인지와 무엇이 외부 AI로 전달될 수 있는지를 사용자가 확인하게 하는 것이다.

## 3. 목표 사용자와 핵심 작업

### 1차 사용자

- 여러 서비스에 수년간 기록을 쌓았지만 개발 도구를 사용하지 않는 개인
- 자신의 글을 바탕으로 회고, 글쓰기, 연구, 업무 정리를 하는 지식 노동자와 창작자
- 클라우드 AI는 사용하지만 전체 개인 자료를 한 사업자에게 맡기고 싶지 않은 사용자

### 사용자가 해결하려는 작업

1. 내가 권한을 가진 기록을 한곳에 가져온다.
2. 서비스가 바뀌어도 읽을 수 있는 형태로 보존한다.
3. 과거에 무엇을, 언제, 어디에 썼는지 찾는다.
4. AI가 답할 때 내 기록의 근거와 원문 위치를 함께 받는다.
5. 특정 출처나 기록을 제거하면 검색·AI 제공 대상에서도 제거한다.
6. 다른 PC나 호환 도구로 내 데이터 자산을 옮긴다.

## 4. 확정된 제품 원칙

- **글로벌 우선:** UI 기본 언어는 영어로 시작하되, 데이터와 검색은 Unicode를 보존하고 한국어를 필수 품질 벤치마크로 둔다.
- **설치형 제품:** 비개발자는 별도 데스크톱 앱 설치를 감수한다고 가정한다. 최종 사용자에게 터미널, Docker, 데이터베이스 설정, AI API 키를 요구하지 않는다.
- **Windows 우선:** 첫 설치판은 Windows x64만 대상으로 한다. macOS 지원과 수치형 최소·권장 하드웨어 사양은 실제 패키지 측정 전까지 보류하며, 검증하지 않은 호환성이나 성능을 주장하지 않는다.
- **첫 공개 베타 무료:** Windows 공개 베타 설치 파일에는 결제나 라이선스 키 장벽을 두지 않는다. 현재도 로컬 개발자가 무료·무키 형태의 unsigned Windows x64 EXE를 만들 수 있지만 비공개·비민감 평가용일 뿐이다. 무료 배포 결정이 오픈소스 권한을 대신하지는 않으므로 공개 전에 별도의 소프트웨어 라이선스를 확정한다.
- **로컬 우선:** 가져오기와 로컬 검색은 계정 없이 동작한다. 다만 클라우드 AI가 검색 결과를 요청하면 선택된 발췌문은 기기 밖으로 나갈 수 있음을 명확히 알린다.
- **원문과 출처가 자산:** 임베딩은 다시 만들 수 있는 색인일 뿐이다. 정규화 원문, 출처, 작성·수정 시각, 리비전, 사용자 주석, 삭제 계보가 핵심 자산이다.
- **합법적 경로에 기술 중립:** 공식 내보내기, 읽기 전용 API, 사용자가 선택한 로컬 파일, RSS/Atom, 사용자가 권한을 가진 웹 캡처 등 합법성이 확인된 획득 경로를 방식만으로 배제하지 않는다.
- **최소 권한:** 초기 MCP 도구는 검색과 조회만 제공한다. 가져온 문서의 문장은 데이터이며, 앱 권한이나 명령이 아니다.
- **이식 가능성:** 장기적으로 공개 명세의 `.ownctx` 묶음으로 원문·메타데이터·체크섬을 내보낸다.

## 5. 범위

### 첫 번째 동작 가능한 수직 슬라이스

- 사용자가 선택한 폴더에서 지원·제외·용량 초과 항목을 먼저 확인한 뒤
  UTF-8 Markdown·텍스트 파일 가져오기
- 로컬 SQLite 저장, 리비전과 출처 보존, FTS5 검색
- 문서 단위 삭제와 검색 색인 제거
- 출처가 포함된 검색 결과와 안정적인 문서 조회
- 로컬 `stdio` MCP의 읽기 전용 `search`, `fetch`
- 폴더 선택, 내장 샘플, 로컬 검색, 출처 제거를 제공하는 데스크톱 UI
- Codex 설정과 Claude Code user-scope `owncontext` 설정의 미리보기·연결·해제
- MCP 프로세스별 단일 `default` 컬렉션 허용과 그 밖의 컬렉션 기본 거부

내장 샘플은 main process가 신뢰된 앱 데이터 경계 안에서 고정 파일
목록을 생성하며, 사용자에게는 물리 경로 대신
`owncontext-sample://library/v1/` 가상 provenance URI를 표시한다. renderer는
샘플 경로나 URI를 임의로 전달할 수 없다. 이는 일반 가져오기에 쓸 수
있는 provenance 덮어쓰기 기능이 아니다.

### 후속 베타 범위

- Notion 내보내기 ZIP, 블로그 RSS/Atom, 범용 HTML·JSON·CSV
- 공식 읽기 전용 OAuth 커넥터
- 미러와 스냅샷 동기화 방식의 명시적 선택
- 사용자가 선택하는 컬렉션별 AI 클라이언트 권한, 만료, 접근 이력
- 서명된 Claude Desktop Extension (`.dxt`)
- 이식 가능한 내보내기·가져오기와 완전 삭제 영수증
- 검증된 다국어 하이브리드 검색과 선택형 로컬 임베딩

### 의도적으로 제외하는 것

- 범용 AI 채팅 UI와 자체 기반 모델 제공
- 사용자를 대신해 게시물을 작성·수정·삭제하는 MCP 도구
- 자격 증명 우회, 접근 통제 우회, 사이트 제한 회피
- 출처가 사라지는 무제한 데이터 긁어오기
- 검증 없이 “완전한 오프라인”, “암호화됨”, “프라이버시 보장”이라고 주장하는 마케팅

## 6. 비개발자 핵심 경험

```text
앱 설치
  → 데이터 위치 선택 또는 서비스 연결
  → 가져올 범위와 권한·외부 전송 경계 확인
  → 미리보기 후 가져오기
  → 내 기록에서 검색하고 원문 확인
  → 지원 AI 앱 선택
  → 변경될 설정을 미리 보고 연결
  → AI 답변에서 출처 열기
  → 연결 해제·출처 삭제·내보내기
```

### 필수 UX 규칙

- 첫 실행은 샘플 데이터로 체험할 수 있어야 한다.
- 연결 버튼을 누르기 전에 읽을 수 있는 데이터 범위와 외부 전송 가능성을 보여준다.
- AI 설정 파일을 바꿀 때 원본 백업과 변경 미리보기를 제공하고 되돌릴 수 있어야 한다.
- 검색 결과는 제목, 발췌문, 원본 위치, 시각, 안정 ID를 표시한다.
- 동기화 실패와 “검색 결과 0개”를 구분해 설명한다.
- 삭제는 원문 참조, 리비전, 청크, 파생 색인의 제거 범위를 보여주고 검증 가능해야 한다.

현재 개발자 알파의 첫 실행 샘플과 Codex·Claude Code 연결 화면은 위
흐름의 일부를 구현한다. 일반 폴더 가져오기는 물리 경로를 renderer에
보내지 않는 내용 비공개 사전검사를 거치며, 5분짜리 단일사용 확인 토큰에
묶인다. 확인 시 승인된 지원 파일 범위가 다시 검사한 범위와 일치하지
않거나 가져올 후보가 0개면 금고를 변경하지 않는다. 현재 지원 형식은
UTF-8 `.md`와 `.txt`뿐이며, 다시 가져올 때
폴더에서 사라진 기존 문서를 자동 삭제하는 미러 동작은 아직 제공하지
않는다. Claude Code 연결은 user scope를 사용하고 절대
경로의 `CLAUDE_CONFIG_DIR`을 존중한다. 현재 UI가 부여하는 컬렉션은
`default` 하나로 고정되어 있으며, 사용자가 컬렉션을 선택하거나 권한
만료나 컬렉션 선택을 관리하는 기능은 아직 구현되지 않았다. 접근 이력은
요청 시각·유형·선언된 클라이언트 종류·결과 수만 로컬에 기록하며 질문,
본문, 제목, 경로, 문서·청크 ID는 표시하지 않는다. 클라이언트 종류는
관리된 실행 환경의 선언이지 인증된 프로세스 신원은 아니다.
반환될 수 있는 정보는 본문 발췌뿐 아니라 제목, 원본 경로, 시각, 안정 ID
등의 provenance 메타데이터도 포함한다. 현재 검색 이벤트는 로컬 UI와 각
외부 클라이언트의 선언을 구분하지만 실제 공급자 수신·보관이나 모델 호출을
증명하지는 않는다. 임시 프로필의 패키지 호환성 검사는 Codex 설정의 정확한
파싱과 Claude Code의 `owncontext` 연결 상태 및 임시 금고 생성, 검색·조회
이력 0건을 확인한다. 인증된 클라이언트 실행 파일과 실제 모델·도구 통합은
공개 전 게이트다. 셸에서만 지정한 `CLAUDE_CONFIG_DIR` 대상도 업데이트·삭제
환경을 넘어 아직 추적하지 못한다.

## 7. 데이터 획득 정책

“합법적이면 모두 허용”은 제품 방향이며, 개별 사이트에 대한 법률 판단을 자동으로 보장한다는 뜻은 아니다. 커넥터는 출시 전에 다음을 기록하고 통과해야 한다.

1. 사용자가 해당 자료를 가져올 권한 또는 적법한 근거가 있는가
2. 공식 내보내기나 API가 있다면 그것을 우선했는가
3. 인증 정보와 세션을 최소 권한으로 보관·폐기하는가
4. 서비스 약관, 로봇 정책, 저작권, 개인정보, 지역 규정의 확인이 필요한가
5. 요청 속도·범위·첨부파일 크기에 안전 한계가 있는가
6. 원본 삭제·접근 철회·계정 연결 해제 시 로컬 사본의 의미가 사용자에게 명확한가
7. 재현 가능한 테스트 fixture와 출처·삭제 계보가 있는가

판정이 불분명한 커넥터는 코어에서 막는 것이 아니라 배포 레지스트리에서 보류한다. 사용자가 직접 선택한 파일과 공개 규격의 내보내기는 가장 먼저 지원하고, 계정 자동화나 브라우저 캡처는 서비스별 검토 뒤 추가한다.

## 8. 검색 및 AI 제공 계약

- 1단계 기준선은 SQLite FTS5다. 다국어 fixture에서 측정하기 전에는 대형 임베딩 모델을 필수 설치하지 않는다.
- 검색은 접근 가능한 컬렉션으로 먼저 제한하고, 결과가 만들어진 뒤의 필터는 추가 방어로만 사용한다.
- AI에는 질문과 관련된 제한된 청크, 출처 메타데이터, 안정 ID를 제공한다.
- `fetch`는 금고가 발급한 안정 ID만 받으며 임의 파일 경로, URL, SQL을 받지 않는다.
- 검색·조회 이벤트에는 클라이언트, 시각, 반환 문서 ID를 기록하되 질문 전문과 본문을 기본 로그로 남기지 않는다.
- 가져온 문서 안의 프롬프트나 명령은 인용 가능한 텍스트일 뿐 도구 권한을 바꾸지 않는다.

현재 프로토타입은 반환 행을 허용된 컬렉션으로 제한하지만 FTS 후보를
만드는 가상 테이블은 전역 하나다. 따라서 다른 컬렉션의 본문이
반환된다는 관찰은 없더라도 후보 작업량, 캐시·자원 효과, 응답 타이밍이
컬렉션별로 완전히 분할되었다고 주장할 수 없다. 공개 전에는 후보 생성
자체를 물리적으로 분할하거나 충분한 비간섭(side-channel) 테스트로 이
경계를 검증한다.

## 9. 성공 지표와 출시 게이트

### 사용자 가치 지표

- 새 사용자가 터미널 없이 첫 자료를 가져오고 검색하는 데 걸리는 시간
- 검색 결과에서 원하는 원문을 찾은 작업 성공률
- 출처 링크가 유효하게 열리는 비율
- AI 연결 후 인용된 개인 기록이 실제 질문을 뒷받침하는 비율
- 연결 해제와 삭제를 사용자가 스스로 완료하는 비율

수치 목표는 사용성 테스트 표본과 기준선이 생긴 뒤 정한다. 현재 단계에서 임의의 퍼센트를 성공 기준으로 만들지 않는다.

### 공개 베타 전 필수 게이트

- 데이터베이스, 파생 색인, 임시 파일, 백업의 저장 암호화와 OS 키체인
  - 현재는 고정된 Windows x64 암호화 SQLite 후보와 `safeStorage` 키 생명주기를
    별도 패키지 스모크에서 생성·검색·종료·동일 프로세스 재개방까지 검증했다.
    일반 데스크톱/MCP는 여전히 평문이며, 재현된 WAL 동시 경합과
    강제종료·내구성·프로세스 잠금·DACL·회전·브로커 통합은 미해결이다.
- Claude 설정 전체 백업의 암호화·보존 한도·발견·삭제 정책. 전체 백업은
  OhMyContext 밖의 비밀을 포함할 수 있고 변경 때마다 누적될 수 있다.
- Claude 설정 교체와 백업의 Windows DACL 보존, 외부 동시 저장을 덮지 않는
  원자적 교체, 사용자 지정 `CLAUDE_CONFIG_DIR` 대상의 업데이트·삭제 추적
- Codex·Claude 실행 파일의 출처, 서명·publisher, hash, 지원 버전 검증
- 서명된 설치 파일과 업데이트, SBOM, 의존성·파서 격리 검토
- Windows x64 설치판의 설치·실행·삭제·검색·MCP 동작 검증과 측정 환경 공개
  (GitHub 제공 임시 Windows 러너 전용 자동화는 구현·정적 검증됐으나 최초
  실제 설치·제거 실행은 아직 완료되지 않음)
- 전역 FTS 후보·캐시·타이밍까지 포함한 교차 컬렉션 비간섭, 삭제 후 검색,
  악성 문서, 대용량·깨진 파일 회귀 테스트
- 개인정보 처리 설명, 보안 신고 채널, 라이선스 확정

## 10. 오픈소스와 지속 가능성

프로젝트 라이선스 결정은 후보군을 좁히지 않은 채 보류한다. 공개 릴리스
전 별도 검토로 확정하며, 그전에는 외부 배포와 기여를 받지 않는다.

코어 기능은 계정 없이 로컬에서 사용할 수 있어야 한다. 향후 지속 가능한 선택지는 관리형 암호화 동기화, 다중 기기 백업, 검증된 프리미엄 커넥터 운영처럼 로컬 코어의 데이터 소유권을 훼손하지 않는 서비스다. 유료화 여부와 가격은 초기 사용성·운영 비용 검증 이후 결정한다.
